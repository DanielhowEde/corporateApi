⚠ This is a destructive action

Regenerating the Certificate Authority will:

  • Invalidate every one of the {{ existing_key_count }} client certificate(s) currently issued. They were signed by the old CA and will stop working against any service that trusts only the new CA.
  • Archive the current CA to data/keys/_ca.archived.<timestamp>/ — it is not deleted and can still decrypt anything it previously signed.
  • Push the new CA to low-side via the gateway. Low-side's uvicorn trust store will pick it up on next restart with the appropriate --ssl-ca-certs flag.
  • Mark every existing key pair's metadata with status: orphaned. Until you re-issue them, no client will be able to authenticate via mTLS.

Recommended only if you're renaming the CA's identity (e.g. after a company rebrand) or rotating a suspected-compromised CA key.
